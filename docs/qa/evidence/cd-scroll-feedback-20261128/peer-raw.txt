Remaining objections
“Retained” warnings are overwritten by the next healthy action (source-backed).
retainReminderWarning keeps a warning only until reportStatus replaces it. runReminderFeedbackAction always reports a new status, so a later “Reminder saved locally.” erases an unresolved “N alerts may still show titles” warning. The exposure is still there.
Fix: keep warnings in their own slot, keyed by kind, cleared only by a verified-clean result for that kind. setReminderTitlePreference would need to return a typed result for that, not a string.
The new test only checks that a warning is retained when the next status is null. It never covers a later info overwriting it.
No way to clear a warning or error yourself (usability). ChatGPT is right that stale warnings can’t safely auto-clear. But with no dismiss and no “check again” control, a resolved warning (for example the user fixed settings) stays until some action replaces it. Add a “Check again” that re-verifies, and clears only on success.
Modal fatigue (source-backed).
For row actions, every warning triggers Alert.alert('Alert warning', …).
Warnings that are standing conditions, such as notifications turned off or fewer than all reminders queued (which happens whenever more than 48 are eligible), would pop a modal on every Complete or Delete.
Better: modal only for failures and for a new or changed warning, and inline otherwise.
Double speech on iOS (hypothesis, native gate). The same message is announced and then shown in a system alert, so VoiceOver may read it twice or one may interrupt the other. “Alert warning” is also an overloaded title, since the app’s own alerts and dialog alerts are different things.
Classifier coupled to hand-typed copy (source-backed).
reminderResultFeedback matches the exact string from reminder-alerts.native.ts, and the test uses its own typed copy of that string.
If the native message wording changes, healthy outcomes silently become warnings with no test failure.
Fix: export the message template from one place, or add a contract test that reads the real string.
Android repeated identical message (acknowledged gate). A cheap candidate: give the status object an id and key the live region on it. Not a claim that it works.
