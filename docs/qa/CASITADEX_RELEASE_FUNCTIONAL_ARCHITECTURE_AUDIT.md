Classification: **accepted** means current source and required native evidence; **implemented/unverified** means code exists but an acceptance gate remains; **partial** means an integration or workflow is incomplete; **defective** means observed failure or source-proven behavior; **external** means a credential, platform, store, or owner dependency. No module is classified fully accepted for release.

## Required end-to-end journeys and transition checks

1. First launch → Home → Add text memory → Save → Details → Edit fields → Save → Find → relaunch offline → exact retrieval. Repeat with dirty Cancel/Back, validation failure and interrupted write.
2. Add Photo Memory → picker cancel or select → Save → Photos gallery → tapped original → Next/Previous/swipe/zoom → Close → same originating item → replace first slot → relaunch offline → Share preview and native sheet. Check five-photo limit and removal.
3. Details linked reminder → permission opt-in/denial/recovery → scheduled OS record → app death/relaunch → delivery → complete/reschedule/archive → native cancellation. Separately create/edit/complete/delete standalone recurrence and reboot.
4. More → Spaces/Categories create/rename/remove impact → backup export/readback → fresh disposable restore preview/conflict/cancel/confirm → relaunch, media and reminder reconciliation.
5. Run each at normal and 200% text, light/dark, portrait/landscape; record focus order, spoken labels, controls, errors, safe-area and keyboard reachability on Android and iOS.

## Implementation order and dependencies

1. Build current committed source on disposable Android QA. Confirm app identity and embedded source; run linked/standalone alarm, Save/Cancel, photo and memory journeys. Preserve the earlier accepted device data.
2. Restore supported iOS Simulator installation on an isolated target. Require stock screenshot, media import and XCTest handshake before product runs. No accepted simulator reset.
3. Fix failures found in those journeys, with focused regression tests, then rerun affected native paths. Reconcile Home draft and tab behavior against final owner-approved Figma baseline.
4. Run full backup/restore and accessibility acceptance; qualify security/dependencies and sandbox entitlements. Production signing, billing and physical iPhone signoff remain exact external gates.

Evidence must record commit, APK/app checksum, device/runtime, input fixture, steps, actual persisted/readback state, screenshot/log path and outcome. Existing source-only or older-binary PASS never upgrades a current native gate.
