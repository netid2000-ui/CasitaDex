# Media-aware legacy replacement guard — October 15 2026

Before activating media-v2, audited the existing sqlite-repository text-only save/recover: replace() unconditionally deletes cards and spaces. Once media_v2 has committed rows referencing cards, this is not an acceptable overwrite path. Added a fail-closed guard in replace(): probe sqlite_master for media_v2; if the table exists and has nonzero rows, reject legacy text-only replacement before DELETE FROM cards. No data is deleted by the guard. A future media-aware replacement must stage files and commit metadata together, then provide recoverable snapshots.

Scope and limitation: This prevents destructive legacy replacements once media_v2 is populated. It does not create cards' attachments, select images, register media tables, migrate existing attachments, package portable media backups, or solve an all-or-nothing filesystem+SQLite commit. It is source-only, not a native acceptance test. Source-contract regression verifies the guard ordering; it is not a fault-injected SQLite integration test. Validated 96/96 npm tests, npm typecheck, npm lint pass. No APK rebuilt. Existing dirty docs/RECOVERY_RUNBOOK.md preserved; no remote push, Production or physical device change.
