How to use this checklist
Copy this SOP for each project. Leave every checkbox open until the action is complete and supported by evidence. Record reviewer initials, date, status and an evidence identifier for each item. Use an attached evidence register when the space is insufficient. Mark N/A only with a reason and reviewer. A handoff or prior test report is historical evidence until its scope and version are confirmed.
Status values: Not started, In progress, Blocked, Verified, Owner Accepted, or N/A. Competency tracking uses Researched, Implemented, Verified and Owner Accepted. Research, connected libraries, successful builds and visual approval each prove different things.

Verification criteria and evidence
For normal text, target at least 4.5:1 contrast; for large text, at least 3:1. Verify applicable non-text UI contrast at 3:1. Record the measured colors, state and method. Unavailable controls must remain understandable with an explanation where useful. Do not use color alone to convey meaning.
Use current platform guidance for touch targets and text scaling. As working baselines, check 44 by 44 pt Apple targets and 48 by 48 dp Android targets, with spacing and exceptions reviewed in context. Test actual devices; a Figma frame or browser preview does not prove native behavior.
Each evidence entry records: item ID, baseline node or asset version, repository commit or working tree snapshot, build identifier and hash, device and OS, check method, observed result, screenshot or report path, reviewer and date. Record skipped tests and limitations explicitly.
