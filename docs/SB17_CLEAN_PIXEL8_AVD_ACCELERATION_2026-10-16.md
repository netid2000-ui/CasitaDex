`FA_Pixel8_Optimized_API35` via installed official Android avdmanager and `pixel_8` hardware definition (1080×2400, density 420, Google APIs Android 15). Official Pixel device artwork preinstalled with Android Studio at `C:\Program Files\Android\Android Studio\plugins\android\resources\device-art-resources\pixel_8` (`back.webp`, `mask.webp`, `layout`); no unverified 3rd-party skin download required. `showDeviceFrame=yes` retained. Do not run both AVDs simultaneously on this host without a resource plan.

Two separate Android SystemUIService ANR events persisted after 26H2: 20.026s wait on adb reboot and 20.020s wait using temporary `-gpu auto`/SwiftShader. Original QA card `QASecondary2026`, answer `EditVerified2026`, and `Attached image` recovered; old AVD preserved. Exact evidence `SB17_POST_WINDOWS_26H2_SECONDARY_QA_2026-10-16.md`.
2. New Pixel 8 first fresh boot started 00:17:03 Central with 2 cores, 2560M RAM, GPU Auto, snapshots bypassed. Auto selected Google SwiftShader. `sys.boot_completed=1` and boot animation stopped by ~00:19:17. The first-boot event log showed NO `am_anr` event. Fresh first-boot wall time is a provisioning measure, not a normal app launch benchmark.
3. New Pixel 8 temporarily relaunched at 00:21:02 with `-gpu host`: emulator reported `Graphics Adapter Android Emulator OpenGL ES Translator (Intel(R) HD Graphics 630)` with OpenGL ES 3.0 and WHPX active. Android `boot_completed=1`, boot animation stopped by 00:21:40 (checked ~39s after command), no `am_anr` event observed at ~00:21:57.
4. Under host graphics, full non-wiping `adb reboot` issued at 00:22:18. Android `boot_completed=1` and boot animation stopped by 00:23:08; at 00:23:22 the native launcher was focused and event log again showed no `am_anr`. This passed one repeat-boot check on this clean device. Not a multi-hour stability certification.
5. With emulator stopped gracefully, new AVD's `hw.gpu.mode` was changed from auto to **host** (persisted config hash `BB5E7C94109D0F58A8899B50A74FDB48FCABB43A4E4CC472743D64B5093A3B76`). Relaunched at 00:24:11 with NO `-gpu` flag: emulator logs again identified Intel HD Graphics 630, proving persisted default; final boot/event status to be recorded separately when observed.

## Deliberately not applied
- No BIOS/UEFI or Hyper-V feature changes: WHPX already works. Installing/changing hypervisors cannot be justified from present results.
- No Defender/antivirus exclusion: broad SDK or AVD exclusions weaken malware protection and hide supply-chain threats; no scan-related I/O bottleneck measured. If later proven necessary, review narrowly with explicit owner/security approval.
- No High/Realtime priority: could starve Windows UI/agent and other development services; no scheduler starvation diagnosed. Normal priority retained.
- No AVD wipe/reset, hardware graphics forcing on original AVD, simultaneous emulators, OS restart, physical Android phone changes or installed CasitaDex package changes.

## Critical late finding — no durable ANR fix
The **third clean-A VD cold start** at 00:24:11, after persisting `hw.gpu.mode=host` and launching with no GPU CLI override, selected Intel HD 630 as expected BUT then logged **`am_anr: com.android.systemui/.SystemUIService waited 20006ms`** at 00:25:01.797. UIAutomator confirmed `System UI isn't responding` dialog on the clean Pixel 8. This AVD did **not** have CasitaDex Staging installed (`pm path com.designsbyfa.casitadex.staging` returned no package). We selected **Wait**, `sys.boot_completed=1`, and recovered the Android UI without reset.

**Interpretation:** initial ~39s boot and one successful `adb reboot` with Host GPU are genuine performance observations, but repeated cold-start stability is FAIL. The original AVD-specific corruption thesis is weakened: the clean AVD and a system process exhibit the same stall with no CasitaDex APK. We cannot claim root cause has been proved, nor that `-gpu host`, added RAM, official skins or Windows 26H2 cured the issue.

The disposable Pixel 8 AVD was stopped gracefully and its GPU config **reverted to `hw.gpu.mode=auto`** (Google's recommended general default). Original Pixel 5 config/data untouched. Further cold-start Auto comparison is pending. Do not claim complete SB-17 acceptance, and do not make Windows Defender exclusions or High priority changes just to mask a System UI ANR.
