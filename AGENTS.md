# Designs by FA project operating instructions

## Required research and project context

Before planning, implementing, designing, testing, reviewing or releasing work in this repository, read [professional standards](docs/governance/PROFESSIONAL_STANDARDS.md), [QA workflow matrix](docs/qa/research-informed-workflow-matrix.json) and the applicable current project handoff. The governing research checkpoint is [2,200 new hostname reviews in 14 disciplines](https://github.com/netid2000-ui/event-command-by-fa/blob/1933e4a9ae5323c1a59b77f9876e3f17a746f925/docs/research/professional-research-final-five-20261125.md); source registers and revisions are available in the [shared research library](https://github.com/netid2000-ui/event-command-by-fa/tree/work/private-device-planning/docs/research) with authorized repository access.

Select the relevant disciplines for the request, consult their synthesis and directly applicable source references, and record what changed in the decision or acceptance criteria. Verify current authoritative product documentation when APIs, platform rules, costs or policies can change. Do not treat source counts, courses, historical results or summaries as certification. Do not require reading all 2,200 sources for every small change: follow the index and relevant evidence; expand when unresolved.

## Project governance

- Owner-approved Figma is design authority; GitHub source, evidence and decisions are engineering authority. Preserve accepted builds and do not silently substitute a historical runtime for the current accepted baseline.
- The designated Mac mini is exclusive for builds and tests. Record source SHA, actual installed bundle/build identity, exact tools, platform, fixture, expected outcome and evidence. Simulator/emulator first, physical Samsung next, owner physical iPhone final acceptance. Keep required simulators visible and avoid unused emulators.
- Work on feature branches. Maintain a charter, implementation changes, native verification, Figma reconciliation, evidence and handoff. No release merge, store submission, live purchase, production data write, or new paid subscription without owner authorization. Do not use cloud builds as a substitute for the Mac authority.
- Use synthetic records in QA; preserve user data and accepted builds. A successful typecheck, test, opened screen, or design node is not native workflow acceptance. Document missing, blocked, skipped and failed checks. Tests of production integrations require separately authorized, isolated test endpoints.
- Consult existing package scripts and tool inventory before adding dependencies. Prefer already-owned/free tools; benchmark additions against real coverage or cost gaps.
- For changing UI, map complete entry, actions, alternative/disabled/error states, keyboard, Back/Cancel/Save/return, both themes, text scaling and screen reader behavior to approved Figma. Distinguish approximate family mapping from exact control mapping and native evidence.

## Automated QA

On the designated Mac, source `scripts/fa-mac-env.sh` to resolve the existing Java, Android SDK/ADB and Maestro installations. Read back their versions and device identities before native work. No global profile or new package is required.

Use `node scripts/fa-research-qa.mjs --plan` to validate the mapped test-file references and see available existing commands. On the designated Mac mini, `--run --expected-host <observed-hostname> --evidence-root <approved-external-evidence-folder>` records a local source-only typecheck, existing test suite, and lint, with explicit pass/fail/blocked status. It does not install, build, deploy, purchase, touch a physical device, or run native flows. Native cases are a separate stage requiring the recorded current build and synthetic fixture. Use project-specific native procedures; run nothing against live endpoints.

## CasitaDex project specifics

- Preserve the owner-accepted SB40 lineage and later owner-approved changes. The four primary tabs are Home, Photos, Reminders, Find, in that order; Settings is reached beneath the Home date header.
- Local-first, durable offline data and separately stored photos. Title required; Description replaces Answer; use optional taxonomy and clear return paths.
- Approved tiers: Free includes 20 memories; Plus is a one-time $25.99 purchase with unlimited memories, photos, backup and recovery. Household sharing is deferred. Use sandbox checks only; no live checkout.
- Check Expo version in package.json and verify version-matched documentation before API changes. Preserve existing package manager and lockfile. Use existing npm scripts, do not install new dependencies solely to run QA. Native projects generated by Expo must be handled through existing config/plugins and project-specific build documentation.
